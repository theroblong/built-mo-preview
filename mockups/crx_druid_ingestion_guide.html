1
Run the preprocessing script
Converts raw BP222 CSV to clean Parquet — parses Circana date/currency formats, adds derived columns.
bash
# Install dependencies if needed
pip install pandas pyarrow

# Run MO_74 — point to the raw BP222 CSV
python scripts/MO_74_crx_bp222_preprocess.py \
  "/path/to/(BP222) Daily Inventory Status by Warehouse_Aevah (1-1-2023_8-30-2026).csv" \
  --output outputs/built_costco_crx_weekly.parquet
Expected console output:
Reading (BP222) Daily Inventory Status... Loaded 5,410,368 rows x 32 columns Output 5,410,XXX rows Dates 2023-01-08 → 2026-08-31 Items 29 distinct SKU descriptions WHs 909 distinct warehouses MVM wks XX,XXX rows flagged as MVM Sparse ~5,300,000 rows with null dollar_sales (~98.0%) Written → outputs/built_costco_crx_weekly.parquet (~XXX MB) Next step: upload to MinIO, then run Druid ingestion spec.
✓
98% null dollar_sales is expected. Most warehouse × item × week combinations have no sales — Druid handles sparse data efficiently. Do not pre-filter null rows; keeping them ensures Warehouses Selling and inventory metrics are accurate.
2
Upload Parquet to MinIO
Upload the output file to the Circana bucket so Druid can read it.
bash — MinIO client (mc)
mc cp outputs/built_costco_crx_weekly.parquet \
   <minio-alias>/circana/costco/built_costco_crx_weekly.parquet
3
Submit the Druid ingestion spec
In the Druid console: Load data → Local disk or S3/MinIO → Paste spec. Replace <bucket> with your MinIO bucket name.
⚠
rollup must be false. Mo needs warehouse-level filtering (selling WHs, region drill-down, WH 847 e-commerce). Rolling up would collapse rows and break those queries permanently.

4
Verify in the Druid console
Run these SQL queries after ingestion to confirm everything landed correctly.
sql — row count + date range
SELECT COUNT(*) AS rows,
       MIN(__time) AS earliest,
       MAX(__time) AS latest
FROM built_costco_crx_weekly
-- Expected: ~5.4M rows, 2023-01-08 to 2026-08-31
sql — distinct items + warehouses
SELECT COUNT(DISTINCT item_desc)     AS items,
       COUNT(DISTINCT warehouse_name) AS warehouses
FROM built_costco_crx_weekly
-- Expected: 29 items, ~909 warehouses
sql — MVM weeks flagged
SELECT SUM(is_mvm) AS mvm_rows
FROM built_costco_crx_weekly
-- MVM = any row where Coupon Units > 0 (instant savings weeks)
sql — DPWPW velocity by week (quick sanity check)
SELECT TIME_FLOOR(__time, 'P1W') AS week,
       SUM(dollar_sales) / NULLIF(SUM(warehouses_selling), 0) AS dpwpw_avg
FROM built_costco_crx_weekly
WHERE unit_sales > 0
GROUP BY 1
ORDER BY 1
✓
If row count, item count, and warehouse count match expectations, the load is good. DPWPW trend should show MVM spike weeks (coupon periods) standing out above baseline.
Schema reference
⚠
1 unit = 1 Club Pack (16 or 18 BUILT Bars, depending on the item). Do not compare unit_sales directly to SPINS base_units without pack conversion.
Column Type Source / Notes
week_ending string (date) time dim BP222 "Time" field. Sunday of Costco Mon–Sun week. Direct join to SPINS week_ending — no offset needed.
item_desc string BP222 "Item". SKU description. Pending UPC crosswalk from Justin (item table).
warehouse_name string BP222 "Venue". Full WH name e.g. "WAREHOUSE 25 RENO". WH 847 = e-commerce.
region string BP222 "Region". 11 Costco regions incl. E-Commerce.
is_mvm long (0/1) derived 1 = Coupon Units > 0 = MVM / instant savings week. Use this as the MVM flag.
dpwpw double derived Dollar Sales ÷ Warehouses Selling. Best velocity metric for Costco. Avoids Club Pack unit confusion.
unit_sales double BP222. 1 unit = 1 Club Pack (16 or 18 bars). ~98% of rows are null.
dollar_sales double BP222. ~98% null — most WH × item × week = no sales. Expected; do not filter.
warehouses_selling double Count of WHs with sales. TDP proxy when divided by ~702 total active selling WHs.
on_hand double Inventory on hand. Multiples of 525 = pallet-level. Not consumer demand signal.
on_order double Pallet ordering signal.
avg_coupon_value double $4.00 or $5.00 for BUILT MVM instant savings events.
fuel_price_regular double Circana-embedded macro signal. ~93K of 5.4M rows non-null.
oos / in_stock_pct double do not use ~100% null. Circana investigating.
