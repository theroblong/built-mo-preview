Meijer Brief — Report Output Product Direction

Monday deadline: Brian's Meijer broker meeting is Sept 29. Brief was delivered Sept 24 and received positively — now needs retailer-safe export capability before that meeting.
Brian's ask: editable PDF with modular sections

Graphs locked; user can edit takeaway/narrative text. Sections can be shown, hidden, or separated — different audiences get different cuts of the same brief.

Rob's concern: HTML exposes internal data

The current meijer_cannibalization_brief.html embeds all its data as inline JSON/JS. A salesperson forwarding this to a Meijer broker gives them view-source access to: competitor UPCs + units, Mo cannibalization probabilities, internal SPINS scores, BUILT-vs-competitor raw numbers. None of that should reach a retailer.

Target users: salespeople / channel people exporting to retailers. Depending on destination, must reduce data and ensure nothing critical is packaged in the file.

Build plan (for Monday)
  • contenteditable on narrative/takeaway blocks — salespeople rewrite before printing
  • Section-level show/hide checkboxes — include or exclude sections per audience
  • "Retailer View" print mode — CSS that auto-hides: raw data tables, cannibal_prob columns, competitor-level detail, internal Mo scores
  • "Export PDF" button → window.print() with Retailer CSS active; charts render as images, no view-source risk
  • Internal HTML stays full; only the PDF is the shareable artifact
Confirm with Brian: which sections should be retailer-visible vs. internal-only? (e.g. check lane recommendation = visible; competitor unit volumes = internal)
Longer-term: server-side auth + RBAC

The real fix is server-side rendering so the file never contains data the viewer isn't authorized to see. This is the MCP+RBAC direction from earlier discussions — right sprint is post-v1 stable. PDF mode is the safe path for Monday.
